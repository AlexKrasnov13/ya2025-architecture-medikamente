# Task3 — Защита данных (at rest и in transit)

Ниже — практичная классификация данных для «Медикаменте» и набор защит, который можно реально внедрять по этапам.

## 1. Какие данные защищаем и почему

| Класс | Что входит | Риск | Почему это важно |
|---|---|---|---|
| C1 Public | Публичная информация на сайте | Низкий | Важны целостность и доступность |
| C2 Internal | Внутренние расписания и справочники | Средний | Нельзя допускать утечки служебной информации |
| C3 Personal | ФИО, контакты, дата рождения | Высокий | Это ПДн, есть юридические и репутационные риски |
| C4 Medical | Диагнозы, анализы, назначения | Критический | Медицинская тайна, максимальный ущерб при утечке |
| C5 Payment | Платежи, чеки, статусы транзакций | Высокий | Риск финансовых потерь и злоупотреблений |
| C6 Audit | Логи доступа и security-события | Высокий | Без них невозможно расследовать инциденты |

## 2. Что делаем для каждого состояния данных

| Состояние | Минимально необходимая защита |
|---|---|
| At Rest | AES-256 для БД/файлов/бэкапов, KMS/HSM, ротация ключей |
| In Transit | TLS 1.2+, mTLS для внутреннего обмена, защита внешних API через gateway |
| In Use | RBAC/ABAC, маскирование, токенизация, контроль выгрузок через DLP |

## 3. Базовый обязательный контур

1. Шифрование at rest для всех C3-C6.
2. TLS/mTLS для потоков C3-C6.
3. Централизованное управление ключами и ротация.
4. Единая модель доступа: RBAC + ABAC + least privilege.
5. Неизменяемый аудит операций с чувствительными данными.

## 4. Автоматизированный контроль

1. Policy-as-code в CI/CD для API и схем БД (проверка PII-тегов и правил доступа).
2. DLP-контроль почты и выгрузок.
3. SIEM/UEBA-правила на аномальные обращения к C3+.
4. Квартальная recertification прав доступа.

## 5. Реестр средств защиты

| Тип | Средство | Для чего |
|---|---|---|
| Программное | API Gateway + WAF | Защита внешнего периметра и контрактов API |
| Программное | IAM/IdP | Централизованный доступ и ABAC-политики |
| Программное | SIEM/UEBA | Мониторинг и алертинг по инцидентам |
| Программное | DLP | Контроль утечек через файлы/почту |
| Программное | СУБД + Object Storage | Хранение с шифрованием и аудитом |
| Аппаратное/сервис | KMS/HSM | Хранение и жизненный цикл ключей |
| Аппаратное/сервис | Backup platform | Резервирование и восстановление |

## 6. Что считаем выполнением Task3

1. Данные классифицированы по риску.
2. Для хранения и передачи выбраны конкретные меры защиты.
3. Есть автоматизированные проверки, а не только ручной контроль.
4. Подготовлен реестр инструментов, которые закрывают эти меры.
